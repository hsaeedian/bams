# Install BAMS on cPanel — no terminal or SQLite

Requirements: PHP 8.2+ with pdo_mysql, cURL, DOM, SimpleXML, and sessions; MariaDB 10.6+ with InnoDB; HTTPS. Select the PHP version/extensions in cPanel or ask your hosting provider. SQLite is not required for this installation.

1. In cPanel **Database Wizard**, create a **new empty MariaDB database**, create its database user, and assign that user **ALL PRIVILEGES on this database only**. Note the full database and username including cPanel's account prefix. You do not need permission to create databases from PHP. Use your host's database hostname (usually `localhost`) and port (usually `3306`).
2. The application now lives at the repository root. Upload its root PHP files, `.htaccess`, and `api`, `lib`, `css`, `js`, `fonts`, `images`, and `plugins` folders with cPanel **File Manager** into, for example, `public_html/bams/`. Alternatively, build `bams-cpanel.zip` with `python3 tools/package-cpanel.py`, upload it and extract it there, then remove the uploaded ZIP. In either case, `index.php` and `install.php` must appear directly in that folder. Do not upload development folders, `.git`, private configuration, or databases. Apache/LiteSpeed must honor `.htaccess` with `mod_rewrite`; other servers require equivalent access rules.
3. Open `https://YOUR-DOMAIN/bams/install.php`. Opening the application redirects here if it is not configured. The page does not need a database connection to display requirements and setup instructions.
4. On the installer, click **Generate and download setup.key**. Keep the page open. In cPanel File Manager settings enable **Show Hidden Files**. Create the exact private folder displayed on the page; on cPanel it will normally be `/home/YOUR-ACCOUNT/.bams-<installation-id>`. Set folder permissions to **0700**. Upload the downloaded `setup.key` there and set its permissions to **0600**. This one-time ownership check prevents another visitor from claiming an uninstalled site. Do not upload it inside `public_html`.
5. Return to the installer. The setup-key field is already filled if you generated it on that page. Enter the full database name/user, database password, first administrator username/display name/password, and confirm the application's HTTPS URL including `/bams/` if used. The administrator password must be 12–72 bytes. Click **Install BAMS**. Use HTTPS before entering passwords. An English/Persian language selector is provided.
6. Follow the **Login** link. Add your BBB or Adobe servers in Administration. No CLI command, SQLite database, SQL import, or manual PHP configuration editing is required.

The installer writes `bootstrap.php` with the MariaDB connection settings in the private folder. It never writes deployment secrets into the public application folder. The folder must be writable by PHP under your cPanel account. Only the private folder needs write access; do not make the public source tree broadly writable. If `open_basedir` prevents PHP accessing a private folder outside `public_html`, ask the hosting provider to allow that private directory. The application does not silently place credentials in a public directory as a workaround.

Installation locks when the private bootstrap or durable `installed.lock` exists. The installer removes its `setup.key` and temporary pending file after success. Revisiting it cannot reset your administrator, change database settings, or overwrite an existing installation. You may remove public `install.php` after successful verification as an additional operator action; normal login and administration do not need it. Do not delete the private bootstrap or lock to reset a password.

Only a dedicated empty database is accepted. Existing application/WordPress tables are never deleted or overwritten. MariaDB's schema creation cannot be rolled back; if installation is interrupted, empty BAMS tables can remain. A private pending token and database ownership marker allow the same installation to retry safely with the **same database and database user**. If interrupted after the administrator was committed, retrying completes configuration publication without changing that administrator's password. Use the original password in that case. Connection passwords are never prefilled after an error; re-enter them. Do not delete partially installed tables or pending files without first reviewing what was created. If abandoning an attempt, preserve its data and use a new dedicated empty database.

Keep `bootstrap.php`, `installed.lock`, and backups private. Use cPanel Backup/phpMyAdmin to export the MariaDB database for backup; protect exports because they contain recoverable server credentials. Back up the private bootstrap separately and restore the matching database/configuration/source together. No encryption key is used: filesystem access controls and private/encrypted backups protect recoverable credentials; administrator/user passwords are hashed.

For an upgrade, preserve the private bootstrap/lock/database and overwrite reviewed public source only. This release supports the earlier SQLite installation without moving its data, but the web installer is for a **new MariaDB installation**, not an automatic SQLite/legacy conversion. If you have not initialized the earlier version, simply upload this version and use the browser installer. An old unused `config.php` is never loaded by web setup; move/remove any real legacy config from the public upload after retaining a private backup. No automatic import of its credentials is performed.

Developer verification still needs a compatible PHP/MariaDB test environment. No claim is made that this archive was installed on your actual cPanel account or joined a live BBB meeting.
